# Key Decisions

A reading-order summary of the trade-offs. For full context per decision, see `docs/adr/`.

| # | Decision | Chose | Rejected | Why |
|---|---|---|---|---|
| 1 | Language / runtime | Python 3.12 + FastAPI | Go, Node, Java | PDF/email parsing ecosystem (pdfplumber, mailparser, pandas) is unmatched. Personal tool — iteration speed > raw throughput. |
| 2 | DB | Postgres 16 | SQLite, DuckDB, MongoDB | Household data fits in a single Postgres; gives us JSONB, window funcs, and a Grafana datasource that just works. |
| 3 | System of record | Postgres | S3 + parquet, raw mailbox | Need ad-hoc SQL for dashboards. Mailbox is the *source*; Postgres is the *materialized* SoR. |
| 4 | Message queue | None | Kafka, Redis Streams, Celery | 6h cadence × ~5 mailboxes = 0 events/sec. APScheduler in-process is enough. |
| 5 | Blob storage | Local filesystem (`./data/raw`) | S3, MinIO | Privacy goal: no external services. Volume mount is fine for tens of MB/month. |
| 6 | Multi-tenancy | None — single household | Row-level security, per-owner schemas | Out of scope. `owner_id` column distinguishes family members. |
| 7 | Auth | None on local network; basic auth at reverse proxy if exposed | OIDC, JWT | Lives behind LAN / Tailscale. Building OIDC for a single-user tool is overkill. |
| 8 | LLM provider | Local Ollama (llama3.2:1b default) | OpenAI, Claude API | Statements contain PAN, salary, account numbers. Hosted APIs are a non-starter. |
| 9 | LLM usage | Fallback only — parsers first, LLM if parser fails | LLM-first extraction | Deterministic parsers are cheaper, faster, and auditable. LLM only covers the long tail of new layouts. |
| 10 | Frontend | Grafana provisioned dashboards | Custom React/Next app | User is the developer; templating + alerting for free; saves weeks. |
| 11 | Categorisation | Regex rules in `categorizer.py` | ML classifier | 50 rules cover >95% of rows; rules are debuggable in 30s, models aren't. |
| 12 | Idempotency | Natural key dedup `(account, date, amount, hash(narration))` | Insert + on-conflict update with surrogate UUIDs | Re-running historical import must be a no-op even if attachments shift order. |
| 13 | Scheduling | APScheduler in-process | Cron, k8s CronJob, Celery beat | Single container, single process — no orchestration to manage. |
| 14 | Deployment | docker-compose on a home server | k8s, bare metal, cloud | Five containers, one host, one user. Compose is the right altitude. |
| 15 | Observability | Postgres logs + FastAPI access logs + Grafana itself | OpenTelemetry, Prometheus stack | For a personal tool, dashboards on the data are more useful than dashboards on the dashboards. |
| 16 | XIRR engine | Custom root-finder: scan for a sign change, then bisect (was Newton-Raphson until 2026-10) | numpy-financial, scipy.optimize, Newton | Newton returned nothing for sign-changing streams and blanked cards. See [ADR-0013](adr/0013-custom-xirr.md), [ADR-0026](adr/0026-returns-from-evidence.md). |
| 17 | Manual assets API | Plain REST writes | Spreadsheet import | PPF/FD update quarterly — a one-line curl is faster than maintaining a CSV. |
| 18 | Untraceable cost basis | Recover it from **evidence** (SGB issue price, PPF transfers + notified rate, demat line × AMFI NAV × bank debit → `derived` trades rebuilt every refresh); otherwise exclude and name it. **Never assume** (the break-even redemption synthesis was removed) | Persist guessed transactions; require manual cost entry | Keeps the rebuild-from-emails invariant while XIRR still uses real returns. See [ADR-0015](adr/0015-synthetic-cashflows.md), [ADR-0026](adr/0026-returns-from-evidence.md). |
| 19 | Goal target dates | Derive from owner DOB + `retirement_age` / child DOB + milestone | Trust the user's static `target_date` | Static dates rot the moment the user's life changes. Derivation keeps SIP honest without manual edits. See [ADR-0016](adr/0016-age-based-goal-dates.md). |
| 20 | Goal projection model | Auto-blended XIRR (capped) + step-up + glide path, with per-goal manual override | Flat single-rate projection per goal | Lets the projection track real holdings without manual tuning, while keeping defaults conservative for goals with no tagged data. See [ADR-0019](adr/0019-goal-projection-model.md). |
| 21 | SIP detection | Cadence (≥3 hits) + amount-stability (CV < 15%) + ₹100 snap + bank-ACH mandate sweep; report per-txn average as current monthly rate | Sum debits ÷ months | Lumpsums and discretionary buys don't masquerade as SIPs; recently-started SIPs aren't under-counted; owners with un-ingested broker mail still get bank-mandate SIPs detected. See [ADR-0020](adr/0020-sip-detection.md). |
| 22 | Historical equity data source | Exact-dated tradebook CSV rows > AGTS fiscal-year aggregates > nothing | Import AGTS as-is; import tradebook on top of existing email-parsed data | AGTS dates a FY's trades to Apr 1 / Mar 31, introducing 0–11 months of error. Tradebook has exact Trade IDs and dates. Email-parsed entries are skipped if tradebook totals already match. See [ADR-0022](adr/0022-tradebook-import-strategy.md). |
| 23 | XIRR transaction scope | Fetch transactions from all accounts, filter by `transaction.isin IS NOT NULL` | Restrict to investment-type accounts | ISIN-tagged SIP debits arrive via bank accounts (mandate transfers), not broker accounts. Narrow scope silently excluded them from per-instrument XIRR. See [ADR-0013](adr/0013-custom-xirr.md). |
| 24 | Ingestion noise: skip known non-statement documents | Silently skip HDFC FT*/CR*/IT_* receipts, TDS certificates, and Union Bank notification letters (<50 KB) | Let parser fail and log an error | These documents contain no transaction history. Counting them as parse errors inflates the error metric and generates useless log noise on every sync. |
| 25 | Where definitions live | One SQL view / one function per number (`v_cashflow`, `latest_holdings_deduped`, `project_all_goals`, `build_positions`); a guard proves pages agree | Each page or panel computing its own | Pages disagreed. See [ADR-0024](adr/0024-single-definitions-and-consistency.md). |
| 26 | Instruments | Ledger: trades give cost/date, month-end demat balances give quantity, every change must be explained | Trusting either alone | See [ADR-0023](adr/0023-instrument-ledger.md). |
| 27 | Bank alert e-mails | Evidence only: matched to statements, shown as "since the last statement", feed today's bank balance; never in income/expense | Counting them as transactions | A payment would exist twice when the statement lands. See [ADR-0025](adr/0025-bank-alerts-as-evidence.md). |
| 28 | Returns | One position model; cost coverage stated, not withheld; plain gain under a year; FDs measured from interest credited or shown as a balance | Per-class / per-goal / per-instrument code paths; hiding a class for one unknown fund | See [ADR-0026](adr/0026-returns-from-evidence.md). |
| 29 | Inflation | One automatic app-wide rate: 10-year average India CPI (World Bank); optional override | Per-goal rates; latest one-year print | A long goal needs the long-run rate. See [ADR-0019](adr/0019-goal-projection-model.md). |
| 30 | PPF | Worth its statement balance (interest credited only on 31 March); return measured between 31-March balances with PPF's own rule at the Government-notified rate (NSI table), reconciled year by year | A typed-in 7.1%, quarterly compounding, accruing interest into the value | Public, official, changes; the year-end balances are the only settled figures. See [ADR-0026](adr/0026-returns-from-evidence.md). |
| 31 | Home loan balance | The lender's prepayment letters, rolled forward by EMIs; a newer figure you type always wins | A hand-kept number | See [ADR-0026](adr/0026-returns-from-evidence.md). |
| 33 | Deposits and PPF | History comes from the monthly statements (principal, interest accrued, maturity value, PPF balance series), kept in `deposit_snapshots`; a deposit absent from the newest statement is closed | Current-state rows overwritten each month; typed rates | See [ADR-0026](adr/0026-returns-from-evidence.md). |
| 32 | Change discipline | Cross-page invariants (`app/invariants.py`) run as a live guard and in tests with mutation checks; UI↔API contract test; figures baseline; pre-push hook | Per-fix unit tests only | Fixes kept breaking other pages. See [INVARIANTS.md](INVARIANTS.md). |
| 34 | Public rules | One effective-dated registry (`app/knowledge/rules.yml`, source + dates per entry); code asks for the value on a date; a stale-rule warning each quarter | Limits/rates typed into code; guessing history before the first verified entry | See [ADR-0027](adr/0027-public-rules-registry.md). |
| 35 | Deadlines | One calendar (`/api/deadlines`, Overview card); every item cites a registry rule or its evidence; unknown opening dates are gaps, not guesses; SGB shows maturity only | Dates typed into the UI; a guessed PPF maturity; early-exit nudges | See [ADR-0028](adr/0028-deadlines-calendar.md). |
| 36 | Automatic updates | One pipeline (`app/etl/pipeline.py`) used by the scheduler, the Sync button and reprocess: statements, bank alerts, loan letters, public rules, then rebuild; a visible warning if it stops | A job that only runs when a button is pressed; the same sequence copied in three places | See [ADR-0029](adr/0029-automatic-updates.md). |
| 37 | Live public rules | The RBI repo rate is read from rbi.org.in daily and laid over the registry; agreeing reads refresh `verified_on`, a change becomes a dated entry; nothing is written if the page is unreadable | Editing a file for each RBI move; guessing when a page fails | Tax thresholds, PPF limit, EPF rate stay hand-verified (no official machine-readable page). See [ADR-0029](adr/0029-automatic-updates.md). |
| 38 | Coin orders | One order is stored once, identified by owner, folio, date, side, units and amount, whatever ISIN it was filed under | Identity that includes an ISIN a later alias can correct | A rescan every 6 h would re-insert. See [ADR-0029](adr/0029-automatic-updates.md). |
| 39 | Home loan schedule | Every letter is checked against the roll-forward of the one before; the lender's letter EMI is applied in each paid month (not the lagging debit); what cannot be reproduced is shown with its size | Smoothing a mismatch; hand-kept balance or payoff | Supersedes the debit-amount roll in row 31. See [ADR-0030](adr/0030-home-loan-reconciliation.md). |
| 40 | Loan rate forecast | Repo now + the spread every letter has fitted (1.85%), labelled as a forecast and replaced by the next letter; off when the pattern breaks | A typed expected rate; a forecast without evidence | See [ADR-0030](adr/0030-home-loan-reconciliation.md). |
| 41 | SGB facts | Tranches come from a verified registry (ISIN, price, issue date); unknown tranches are unknown, not guessed; units cost what the bank shows was paid, else the nominal price, flagged | A hard-coded table; a tranche guessed from a name | ISIN IN0020230069 was the wrong series. See [ADR-0031](adr/0031-sgb-evidence.md). |
| 42 | SGB coupons | A credit equal to units × nominal × 1.25% near a coupon date is that coupon: income, and a return flow of the held bond; a bond only the coupons reveal is reported, not added | Coupons as transfers; counting a bond no statement lists | See [ADR-0031](adr/0031-sgb-evidence.md). |
| 43 | Bond held by hand | A Manual Asset SGB is identified by name (notes only as fallback), valued at the statement price of the nearest-maturity held SGB, its coupons are return flows | Gold spot for SGBs (~14% under market); counting only what a statement lists | See the addendum in [ADR-0031](adr/0031-sgb-evidence.md). |
| 44 | Dividends | A credit is a dividend when shares held before the ex-date × per-share amount equals it to the paisa (or ×0.9 after TDS); counted as income and a flow of that stock; unmatched/ambiguous are listed, never guessed | Dividends as "other"; matching by narration alone | See [ADR-0032](adr/0032-dividends-and-tax-lens.md). |
| 45 | Tax lens | FIFO gains from the ledger's trades, rates and exemption by sale date from the registry, tax class from AMFI's category; income, TDS thresholds and tax-if-sold-today per person and regime; what cannot be computed is reported | A typed rate; slab tax without total income; guessed fund types | See [ADR-0032](adr/0032-dividends-and-tax-lens.md). |

Each row above is expanded in its own ADR under `docs/adr/`.
